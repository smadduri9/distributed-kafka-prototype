Distributed message broker

Built a distributed message broker from scratch in Java with partitioned offset-based logs, producer/consumer APIs over a custom Netty binary protocol, replication, failure detection, partition assignment, and Raft-inspired leader election.

Read the code Run it locally

What it does

Log and protocol

  • Append-only partition logs. Produce returns an offset. Fetch reads from an offset. Records stay on disk.
  • A Netty broker on port 9092. Producers and consumers send a binary frame: type, version, length, body.
  • A local UI on port 8080 for topics, produce, and fetch.

Cluster

  • Heartbeats refresh a Redis key for 10 seconds. When the key expires, the controller marks the broker dead.
  • The controller assigns a leader and replicas for each partition and caches that map in Redis.
  • Leaders replicate records and track a high-water mark. Raft-inspired election tracks terms, votes, and the leader.

Path of a record

Producer or consumer Custom binary request over TCP.
↓
Netty broker Appends to the partition file and returns the offset. Fetch starts at an offset.
↓
Controller Assigns leaders and replicas. Each heartbeat refreshes kafkads:broker:{id} with a 10-second TTL.
↓
Replication and leader election Followers acknowledge records. Election advances term, vote, and leader.

Where to look

LogSegment.java Append and fetch by offset. RequestParser.java Type, version, length, body. RedisClusterCache.java TTL liveness and the assignment hash. Controller.java Registration, assignment, dead-broker detection.

Run it

./gradlew test --no-daemon
./gradlew run --no-daemon

Java 11 or newer. Then open localhost:8080. Redis on localhost:6379 stores broker liveness and partition assignments.
